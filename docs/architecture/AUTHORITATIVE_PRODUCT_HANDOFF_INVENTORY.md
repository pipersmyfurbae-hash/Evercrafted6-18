## Governing product contract

> **Memory → Essence → Story → Guided Florals → Recipe → Blueprint → Render → Outcome**

The client supplies a memory once. Evercrafted interprets and verifies the Essence, creates a source-grounded Memory Story and structured Design Signals, curates real candidate inventory, lets the client select floral identity by guided role, locks the complete recipe, composes the Blueprint from that recipe alone, then renders the approved design. The client chooses floral identity; Evercrafted remains the designer.

Story Genesis must not invent personal biography, events, relationships, locations, inventory, flowers, roles, quantities, or wreath construction. It must keep source-grounded fact separate from interpretation, persist version/approval evidence, and block downstream progression until approval.

## Guided and Studio separation

Guided Mode must present one meaningful decision at a time, persistent progress, automatic save/resume, guided role selection, a visible My Wreath tray, controlled revisions, simplified Blueprint review, render approval, and outcome handoff. Studio Mode retains inventory intelligence, scoring, profile and rule tools, blueprint JSON/ECR, render/cost/provider tasks, provenance, build sheets, substitutions, and fulfillment controls. Both use the same data and engines but expose different complexity.

## Core workflow conditions

| Stage | Required decision or validation | Must not occur |
|---|---|---|
| Memory | Capture free writing once and consent separately | Force a client to repeat their memory |
| Essence | Client approves or adjusts the Emotional Intelligence Profile | Run downstream generation from an unapproved Essence |
| Story | Source-grounded story and Design Signals are approved | Preselect inventory, floral roles, or wreath geometry in story prose |
| Guided Florals | Server-curated 3–6 candidates per required role; client may lock/replace/undo | Expose supplier costs, proprietary scores, or silent substitutions |
| Recipe | Transactional, idempotent, versioned lock with completeness gate | Allow Blueprint input outside the locked recipe |
| Blueprint | Deterministic, buildable composition with named greenery pockets | Allow unbuildable conflicts through to rendering |
| Render | Immutable approved manifest, manual provider workflow, review and version history | Let renderer redesign the recipe or Blueprint |
